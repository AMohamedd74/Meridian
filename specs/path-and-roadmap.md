# Path Selection & Roadmap Specification

## Path selection

The user can:
- view all three directions,
- inspect details,
- compare directions,
- select one,
- return without selecting.

Selection must be persisted.

## Path detail

Show:
- why this path may fit,
- what is known,
- what remains uncertain,
- first experiment,
- success criteria,
- initial 30-day direction.

## Roadmap philosophy

The roadmap should reduce overwhelm.

Prefer:
- one current focus,
- a small number of weekly tasks,
- concrete experiments,
- evidence collection.

Do not create a rigid multi-year schedule.

## Planning horizons

Use:
- today/next action
- this week
- 30 days
- 90 days
- longer-term direction

Longer horizons should become less specific.

## Experiments

An experiment should answer an uncertainty.

Bad:
"Research fashion."

Better:
"Contact three denim manufacturers and determine whether you enjoy the operational side of producing a physical product."

Every experiment should include:
- objective
- duration
- tasks
- expected evidence
- completion/reflection step

## Acceptance criteria

- [ ] Selected path persists.
- [ ] Roadmap is generated from the user's profile and path.
- [ ] Roadmap has concrete tasks.
- [ ] Tasks can be completed.
- [ ] Experiment progress persists.
- [ ] User can see current focus.
